## Private PDF reading session (2026-11-01)

SourceImage remains the shared source viewer. Within one mounted document it reuses one in-memory PDF loading task across physical pages, while each page still resolves its existing metadata and private source authorization. The cache key includes owner/device scope, immutable resource identity and the current private URL. No file bytes enter a global cache, Service Worker, IndexedDB or localStorage through this optimization. Already loaded pages can render during a temporary network outage using the existing owner-scoped offline metadata; this does not promise whole-book offline availability or bypass a server denial.

Closing the viewer, changing document/account/device/private URL, or explicitly retrying a failed page destroys the previous loading task. Account/device restoration remounts private page content, while a token refresh for the same owner/device preserves the reader. In-flight metadata/ticket reads reject an identity change before returning or caching data. A new page hides old canvas pixels until its own render completes; cancellation is serialized before reuse of the canvas, and decoded page resources are cleaned after rendering.

The document rotates on the next read after eight distinct pages, sixteen million reported loaded bytes, or eight minutes. These are reuse boundaries rather than a hard memory cap; an individual page can require more bytes. PDF.js streaming and automatic full-file fetching stay disabled, range requests remain bounded, and the existing four-million-pixel canvas limit is retained. Original book/page/Evidence IDs and stored source bytes do not change.
